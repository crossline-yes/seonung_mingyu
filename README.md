# seonung_mingyu

문화유산 사진 처리와 대상 마스킹·복원 파이프라인의 협업용 소스 준비본입니다.

## 이번 공유 범위

- 사진·마스크 입력 검사와 명시적인 마스크 검수
- SAM 2 마스킹을 호출하는 어댑터 코드
- COLMAP 특징점·매칭·희소 복원 실행 및 단계별 기록
- 기존 깊이맵을 재사용하는 대상 점군 융합·메시 생성 코드
- 필수 공용 모듈, 합성 입력 테스트와 새 입력용 설정 예시

이 소스 준비본은 다른 PC에서의 전체 복원 성공이나 최종 모델 품질을 보증하는 결과 보고가 아닙니다.
새 희소 복원부터 새 밀집복원·메시까지의 전체 연결은 아직 미완료입니다.
기존 깊이맵 재사용 경로와 새 사진 앞단 실행을 구분합니다.

## 파일 배치

실행 코드가 상대적인 폴더 깊이를 사용하므로 아래 구조를 유지합니다.

```text
scripts/                         필수 입력 검사·도구 경로 모듈
2차년도/코드/                     파이프라인·SAM 어댑터·검수·테스트
2차년도/설정/공유예시/            새 입력용 설정·이미지 목록 예시
```

원본 사진·영상, 마스크 PNG, 점군·메시, 깊이맵, DB, 모델 가중치와 과거 실행 전체는 포함하지 않습니다.
웹 작업보드·기존 독립 Git 저장소, 회의 원문·기관 문서, 개인 환경과 로컬 운영 기록도 첫 공유에서 제외합니다.
마스킹 편집 UI·3D 편집기·LOD·평가 코드는 별도의 후보 검토 후 추가할 수 있습니다.

## 환경과 설치

- Windows, Python 3.12
- 작은 계획 출력·합성 테스트의 확인 환경: NumPy 2.3.5, Pillow 12.3.0
- 실제 복원: COLMAP 4.2.0 Windows 실행 환경을 별도 설치해야 합니다.
  현재 도구 모듈은 저장소 루트의 `tools/colmap-4.2.0/bin/colmap.exe`와 `plugins/`를 사용합니다.
  바이너리·설치본은 이 저장소에 포함하지 않습니다.
- SAM 추론: PyTorch·SAM 2 소스와 체크포인트, 고정 출처·해시를 담은 source descriptor와 대상 지정 설정이 별도로 필요합니다.
  기본 의존성 파일만 설치해서 SAM 추론 환경까지 준비되는 것은 아닙니다.

프로젝트 루트에서:

```powershell
python -m pip install -r "2차년도/설정/공유예시/requirements-core.txt"
python -B -X utf8 "2차년도/코드/run_pipeline.py" --config "2차년도/설정/공유예시/fresh_sparse.example.json" --plan
python -B -X utf8 -m unittest discover -s "2차년도/코드" -p "test_*.py"
```

`--plan`은 실행 단계만 출력하며 연구 run을 생성하거나 COLMAP·SAM을 실행하지 않습니다.
합성 테스트는 연구 입력과 결과를 사용하지 않습니다. 실제 복원·품질 평가는 별도입니다.

## 실제 사진 작업을 준비하는 순서

1. 공유 권한이 있는 사진을 로컬 `data/local/images/` 등에 준비합니다. 이 경로는 Git에서 제외됩니다.
2. 이미지 목록 예시의 이름을 실제 사진 이름·순서로 바꾼 별도 목록을 만듭니다.
3. 예시 설정을 별도 파일로 복사하고 고유 run 이름·입력 경로·목록·카메라 설정을 지정합니다.
4. 예시의 `mask_generation: null`, `feature_masking: false`는 무마스킹 앞단 예시입니다.
   마스킹 실행에는 별도의 SAM 지정·출처 설정 또는 정확한 마스크 해시를 수락한 검수 기록이 필요합니다.
5. `--plan`과 입력·도구 경로를 확인한 뒤 사용자가 실제 실행을 시작합니다.

`images.example.txt`는 데이터가 포함되지 않은 파일명 예시입니다.
예시 그대로의 실제 복원 실행은 검증하지 않았습니다.
출력은 `2차년도/실행결과/<name>/`에 기록되며 Git에서 제외됩니다.
기존 실행과 같은 이름을 재사용하거나 설정이 바뀐 작업을 조용히 재개하지 않습니다.

## 협업과 공개 범위

이 준비본의 제외 규칙은 명시된 파일만 Git 후보로 허용합니다. 새 파일은 검토 후 허용 목록에 추가합니다.
공개 저장소에 게시할 파일은 커밋 전에 목록과 diff를 확인합니다.
프로젝트 전체에 적용할 새 오픈소스 라이선스는 아직 선택하지 않았습니다.
외부 라이브러리·도구·데이터는 각각의 원래 라이선스와 공유 조건을 따릅니다.
